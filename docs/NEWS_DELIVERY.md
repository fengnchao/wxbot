# 综合新闻订阅与每日投递

## 页面设置

打开 log → 用户分组 → 新闻消息。这里的联系人列表仍来自 `butler_groups.json` 的 `groups["1"]`。
新闻类型、新闻来源和条数适用于这一分组的全部接收人。

- 类型多选：国内、国际、社会、财经、文娱、体育、教育、健康、生活。
- 来源多选：中新网要闻导读、即时新闻、分类频道。这些是同一家媒体的不同官方 RSS 入口，不代表三个独立媒体。
- 每日条数：1～10，默认国内／国际／社会／财经、5 条。
- 保存后下次每日任务读取；不会立即发消息。修改联系人绑定不会覆盖新闻设置。
- 表单草稿留在页面内存，刷新数据或折叠卡片不会丢失；关闭浏览器页面后草稿不保留。
- 保存做校验、版本冲突保护和备份。

设置文件在分组 JSON 旁边，名称为 `<分组文件名不含扩展名>.news.json`。
例如 `data/cache/butler_groups.news.json`，格式如下：

```json
{
  "version": 1,
  "news": {
    "categories": ["domestic", "world", "society", "finance"],
    "sources": ["cns_top", "cns_categories"],
    "count": 5
  }
}
```

未创建文件时使用相同默认值。格式错误时停止任务，不回退到默认配置或默认联系人。

## 获取与内容

读取所选官方 RSS，不爬取整篇文章，不调用模型改写新闻。保留标题、短的完整原文摘要（如果有）、媒体名称和原文链接；内容无从核实时不补写。
只选过去24小时且发布时间不晚于抓取时刻的新闻。先按类别轮流选择，再按链接／近似标题去重。
无法保证不同标题下的同一事件全部识别为重复；缺日期、过期、损坏的源不参与结果。来源不足时少发，全部失败或没有新闻时不发送。

首批来源依据：[中新网官方 RSS 目录](https://www.chinanews.com.cn/rss/)。
接入调研中发现一些新浪和人民网历史 RSS 仍可访问，但内容已过期，因此没有列入可选来源。

## 命令与定时任务

项目根目录：

```powershell
# 仅获取与预览，不发送，不写发送记录
.\.venv\Scripts\python.exe -m butler.news --preview

# 实际投递：只有用户需要立即发送时才运行
.\.venv\Scripts\python.exe -m butler.news
```

支持 `--config <Butler配置路径>`。定时调度使用当前 Codex 对话的每天北京时间09:00任务，不另启动第二个调度器。
Codex、电脑、Butler、wxbot 需保持可用；09:00为开始获取时间，获取完后投递。任务不启动或重启服务。
可分发代码不自动创建其他安装者的 Codex 自动任务，其他安装者需为自己的路径配置每日任务。

读取最新新闻订阅者后逐人调用 Butler `/v1/push`，传 `type=1`、`messageType=1`，接收人仍来自新闻分组。
逐人投递是为了保存每个人的回执，避免部分失败后重发整组。较长简报按完整新闻分段，每段目标约500字以内，保留顺序。
鉴权只在进程内读取，不放命令参数或日志。wxbot仍负责微信窗口选择及发件队列。

## 状态与重跑

运行目录位于分组文件旁边的 `<分组文件名不含扩展名>.news/`：

- `YYYY-MM-DD.json`：当天已生成简报、来源状态和生效配置。
- `delivery.sqlite3`：日期、用户、分段、发送状态与原因。
- `latest.json`：最近执行摘要，log 的新闻设置卡片展示结果。
- `run.lock`：防并发运行锁，进程退出自动释放。

抓取失败不锁死当天，重跑可重新获取。已生成简报当日复用，配置变化从下一份每日简报生效。
已确认发送的用户／分段不重复提交。连接中断、超时、进程在发送期间退出或没有发送成功回执时记为 uncertain，后续运行不重放该段。
未发出的后续分段不会越过 uncertain 段。需要核对时到 log 收发队列查阅；这里不自动清理异常。
明确在入队前被 Butler 拒绝的请求可在后续手动运行时重新提交。
旧模拟任务已有当天标记时，新任务跳过当天，避免从模拟切换为真实后再次发送。

## 本次生效

由用户手动重启 log 加载新的配置接口，然后浏览器强制刷新。Butler、wxbot 无需为新闻功能重启。
