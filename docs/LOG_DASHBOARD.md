# log 管理页面

## 导航

- 消息监控：实时工作流、收发队列、模型与记忆。「消息流转」独立页已移除，旧链接自动打开实时工作流。
- 用户与任务：角色与心跳、定时任务、用户分组。
- 系统设置：配置管理。

默认进入 `?tab=workflow` 实时工作流；原来的 `?tab=wxbot|queue|runtime|heartbeat|jobs|groups|configuration` 链接继续兼容。
联系人／分类列表可收起，900 像素以下自动收起；小屏导航横向滚动。
刷新及15秒自动刷新保留当前筛选、各列表页码、展开状态和滚动位置。
“展开本页／收起本页”操作当前页面的详情。
浏览器仅持久保存排序、列表收起偏好，不保存消息、配置值或密钥；
配置草稿及详情状态保留在当前页面内存中，刷新整个浏览器会丢失草稿。

## 实时工作流首页

工作流按五个服务节点展示：顶部最大的 Codex／模型框，中央单一 Butler，
下方左右收件／发件队列，以及底部单一 wxbot。模型请求、模型返回、收件提交、
回复入队、微信收件与微信发送分别使用有方向的连线；同一个 Butler 接收请求及返回结果。
收件队列、发件队列归 wxbot 管理，页面只读取数据，不改变调度。

- 同时展示多位用户，每条消息只有一个当前位置。卡片显示配置中的 UID、请求 ID／收件序号；群聊另显示成员标识。未知联系人沿用 Butler 的窗口名 UID。
- 点选消息高亮有记录的经过节点，右侧显示工具进度、阶段耗时、失败原因、重试次数与失败到期释放倒计时。没有事件的阶段不推断成功。
- 每次读取结束后 1 秒再刷新，单个请求最多等待 5 秒，不叠加请求。首次载入和断线重连只建立快照；只有新事件触发一次传输光点。没有消息变化时保持静止。
- 暂停动画不影响数据刷新及真实处理。页面切换离开后停止轮询；后台标签页暂停读取。断线显示最近成功读取时间、保留旧快照并暂停动画和倒计时。
- 保留筛选、点选、详情展开和滚动位置。发送成功的记录在末节点短暂保留 15 秒，之后在「已完成」查看；主动推送从发件队列开始，丢弃与成功分别标识。
- 模型和两侧队列显示紧凑的「用户 · 消息摘要」及 UID／群成员，列表可独立滚动；默认载入 8 条，更多可展开。Butler、wxbot 默认展示 2 条，供查看当前中转／发送状态。最多读取 500 条未完成消息／批次及最近 60 轮历史，两类独立限额；超限明确提示到原队列页查看。顶部统计来自全队列，右侧计数及搜索范围为当前载入记录。
- 只读接口：`GET /api/workflow`。底层按 `contact + request_id` 关联 SQLite 与两端过程日志，沿用配置脱敏。不会调用模型、恢复任务或触发微信发送。
- 节点和消息列表显示前 20 个字，长内容以“…”省略；点选后通过 `GET /api/workflow-content?id=...` 按需读取消息正文与回复全文。全文保留换行，切换消息和离页时取消旧请求。

更新此页只需手动重启 **log** 并刷新浏览器；Butler、wxbot 无需重启。
已加载工作流 API 的版本，仅更新布局 JS／CSS 时刷新浏览器即可。

## 消息与队列

实时工作流的最近消息默认最新在前，完整回复及工具日志仍按现有规则分流。
每轮摘要显示用户、时间、队列状态和最近已发生的阶段；异常直接显示原因。
点选消息查看正文、回复全文、各阶段状态和耗时，没有证据的阶段不推断成功。
消息搜索筛选当前已加载的记录，可按用户、UID、群成员及 ID 搜索。

收发队列分为：

| 分区 | 展示顺序 |
|---|---|
| 待处理 | 实际队列序号升序 |
| 异常待核对 | 首次失败时间升序，同时间按队列序号 |
| 历史记录 | 队列序号降序，最新在前 |

三个列表（待合并、模型批次、发件）各自分页，每页50条。
状态筛选只在当前分区内生效；搜索筛选本页。
顶部数量是全队列统计，列表和会话摘要按筛选展示。
异常任务保留“重试／确认已发／立即丢弃”及确认弹窗、审计、恢复命令。
队列调度和失败超时规则没有因页面排序改变。

### 模型失败自动恢复（2026-10-21）

- Butler 明确确认未提交模型输入时，沿用原请求 ID 自动重试，最多尝试3次，等待5／15秒。
- 已提交输入后的超时、断流、进程中断等结果未知任务不自动重放，避免重复执行工具。
- 没有发件结果的失败批次从首次失败起最多阻塞 `queue.failure_discard_seconds`（默认180秒）；
  到期保留消息、错误和审计，将批次结束，允许该会话后续消息继续处理。
- 历史异常没有结构化失败事件时，使用原 `finished_at` 计算期限；重启不重置期限。
- 安全重试耗尽时提前结束失败批次；正在运行的模型请求及已生成发件的批次不被该巡检打断。
- 看板显示下次重试、期限、自动恢复审计；“模型失败已结束”与成功回复分开显示。
- Codex 旧线程恢复被 RPC 拒绝时尝试新建同身份、角色、权限的会话，用户记忆与提醒保留；
  该新会话不携带旧对话上下文。失败详情经脱敏写入 Butler 控制台、运行记录和队列错误。
- 本次需手动重启 Butler、wxbot 和 log，由 wxbot 在运行时处理旧异常；本次没有修改真实队列。

## 配置

六个分类：基础连接、微信收发、模型后端、联系人与策略、日志、高级配置。
默认进入基础连接；搜索覆盖所有分类，搜索结果不受当前分类限制。
未启用模型后端、旧兼容配置、运行事实及固定规则放在高级配置中。
角色与工具权限优先在“角色与心跳”维护，底层策略仍可展开编辑。

常见参数使用开关、枚举、数字、字符串列表和联系人表单；复杂结构支持高级JSON。
列表与联系人表单保留未编辑字段；JSON草稿无效时改用JSON编辑器修正。
参数来源、原键名在详情中，生效方式直接显示在参数说明下。

有改动时底部出现保存栏，显示修改数量和涉及文件；每次保存一个来源文件。
切换分类或业务页面不丢草稿，保存其他文件也不覆盖本文件的草稿和原版本。
仍使用原来的类型与权限校验、注释保留、备份、原子替换和409版本冲突保护。
密钥原值不回传；替换值只在密码控件及页面内存中保留，不写入HTML或浏览器存储。

角色／白名单／分组在后续读取时生效；wxbot、Butler、log启动参数仍需手动重启对应服务。
页面不会自动重启服务，不把文件值当作运行进程已经加载的值。

## 查询接口兼容

- `GET /api/flow` 增加可选 `order=asc|desc`，排序在分页之前。
- `GET /api/wxbot` 增加 `flow_order`，配合原来的 `flow_contact`、`flow_offset`。
- `GET /api/queue` 增加可选 `scope=active|issues|history`、`order=asc|desc`，及
  `inbox_offset`、`batches_offset`、`outbox_offset`；省略仍沿用原查询行为。
- 配置行增加展示元数据 `choices`、`widget`，写接口及规范路径不变。
- 静态文件仅通过 `/assets/` 的固定允许列表提供，不能用于读取任意文件。

记忆／模型事件显示接口当前读取范围（最多100条记忆、100条事件），支持会话和内容筛选。
提醒统一在定时任务查看，服务端在截取前优先读取待执行提醒并按到期时间排序。
