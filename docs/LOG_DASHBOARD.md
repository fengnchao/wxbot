# log 管理页面

## 导航

- 消息监控：实时工作流、收发队列。「消息流转」独立页已移除，旧链接自动打开实时工作流。
- 用户与任务：联系人、定时任务。联系人详情统一管理群昵称、监听、角色／心跳、订阅和记忆。
- 系统设置：配置管理、Telegram 转发。

管理台入口为 `http://127.0.0.1:8788/app/`，根路径 `/` 会 302 到 `/app/` 并保留查询参数。
默认进入 `?tab=workflow` 实时工作流；旧 `?tab=runtime/users/heartbeat/groups` 链接转到「联系人」对应区域。
联系人／分类列表可收起，900 像素以下自动收起；小屏导航横向滚动。
刷新及15秒自动刷新保留当前筛选、各列表页码、展开状态和滚动位置。
“展开本页／收起本页”操作当前页面的详情。
浏览器仅持久保存排序、列表收起偏好，不保存消息、配置值或密钥；
配置草稿及详情状态保留在当前页面内存中，刷新整个浏览器会丢失草稿。

## 实时工作流首页

首页以实时消息列表为主，服务流转概览默认收起，可按需展开查看模型、Butler、
收件／发件队列及 wxbot 的连线。点选消息后显示正文和流转详情；小屏幕详情与列表上下排列。
模型标题按当前接入和实际请求显示提供方及模型名；直接模型模式的连线跳过 Butler。
展开概览后，模型框展示当前请求（或点选的历史请求）的公开思考摘要、工具进度和回复正文。
实时内容约每400毫秒增量读取，正文和摘要各有限额；未提供公开摘要时明确显示暂无摘要。
页面离开、收起概览或切换消息时取消旧读取，避免混入其他请求的输出。
顶部将「进行中异常」和「已结束异常」分开统计，避免把历史失败误认为当前仍在阻塞。
收件队列、发件队列归 wxbot 管理，读取页面不改变调度。

- 同时展示多位用户，每条消息只有一个当前位置。列表显示联系人、状态、时间和消息摘要；UID 与联系人重复时省略，群聊另显示成员标识。
- 失败卡片只显示简短原因，避免堆叠内部错误和技术日志。点选消息查看正文、工具进度、阶段耗时、重试次数与失败到期释放倒计时；没有事件的阶段不推断成功。
- 已结束的微信记录提供「移除」，「清理已结束异常」批量移除全部已结束的微信异常历史，范围不受当前搜索限制。操作需确认，刷新或重启后仍保持移除；进行中及投递结果待核对的记录受保护。这里只清理工作流展示，原始队列、投递凭据及操作审计保留，不撤回或重发消息。Telegram 记录暂不提供此操作。
- 每次读取结束后 1 秒再刷新，单个请求最多等待 5 秒，不叠加请求。首次载入和断线重连只建立快照；只有新事件触发一次传输光点。没有消息变化时保持静止。
- 暂停动画不影响数据刷新及真实处理。页面切换离开后停止轮询；后台标签页暂停读取。断线显示最近成功读取时间、保留旧快照并暂停动画和倒计时。
- 保留筛选、点选、详情展开和滚动位置。发送成功的记录在末节点短暂保留 15 秒，之后在「已完成」查看；主动推送从发件队列开始，丢弃与成功分别标识。
- 展开的服务概览显示紧凑的「用户 · 消息摘要」，节点列表可独立滚动。最多读取 500 条未完成消息／批次及最近 60 轮可见历史，两类独立限额；移除的历史不占载入名额。顶部统计来自全队列，列表计数及搜索范围为当前载入记录。
- 只读接口：`GET /api/workflow`。底层按 `contact + request_id` 关联 SQLite 与两端过程日志，沿用配置脱敏。不会调用模型、恢复任务或触发微信发送。
- 节点和消息列表显示前 20 个字，长内容以“…”省略；点选后通过 `GET /api/workflow-content?id=...` 按需读取消息正文与回复全文。全文保留换行，切换消息和离页时取消旧请求。

工作流历史操作：`POST /api/workflow-delete`，请求头 `X-Wxbot-Workflow-Action: 1`、JSON 及同源校验。
单条请求为 `{"action":"single","id":"消息标识","version":"GET 返回的 delete_version","acknowledge":true}`；
批量请求为 `{"action":"failed","acknowledge":true}`，返回 `{"ok":true,"removed":数量}`。
路径来自服务端配置，单条操作在写事务内校验版本；状态变化或仍在处理时返回 409。

模型实时读取：`GET /api/workflow-stream?id=<批次ID>&after=<游标>`，返回 `events`、`cursor`、
`available`、`reset` 和 `more`。只读服务端配置的本地队列，每次最多300条公开事件；旧记录没有事件时不创建表。
该接口不调用模型，也不触发微信发送。已移除或不存在的工作流记录返回404。

## 回复方式

在「配置管理 → 微信收发」选择 `wechat.typing.mode`，保存后重启 wxbot：

| 值 | 界面名称 | 行为 |
|---|---|---|
| `full` | 全量粘贴 | 等待完整回复，整段粘贴后发送 |
| `chunked` | 分字粘贴 | 等待完整回复，按字数和间隔逐批输入；缺省保持此方式 |
| `streaming` | 流式粘贴 | 接收可发送的最终回答增量，实时追加输入框，句子封口后回车 |

句末主要识别 `。！？!?`，连续标点及结束引号合并；网址、代码和小数不从中间拆开。
正常完成后发送剩余正文；未封口的句子不会因等待超时而自动发送。
每次回车前继续验证对象、焦点、草稿和持久化封口状态，每句确认气泡后才发下一句。
模型摘要、工具进度和中间稿始终不会发到微信。

流断开或进程重启时保留已确认发送的句子，停止剩余内容，不重放模型请求。
已经尝试回车但结果不确定的句子保留待核对；仅清理能严格证明属于机器人的草稿。
后端无法保证最终回答增量、群提及身份只能在最终结果确定等情形，会明确退回完整结果发送。
模型服务是否支持流式，以适配器和服务实际返回为准，不能仅靠模型名称判断。

模型流式功能需重启 **wxbot、log**；经过 Butler 时也需重启 **Butler**，以加载新流接口。
已加载工作流 API 的版本，改动前端需在 `web` 执行 `npm run build` 并刷新浏览器。

## 消息与队列

「定时任务」的 Butler 提醒支持逐条删除。点击「删除」并确认后停止后续执行、从列表移除，保留操作记录；已发送的消息不会撤回。正在投递或状态已变化的任务会拒绝删除，刷新后可重新核对。其他调度器管理的旧任务显示为不可删除，需到对应调度器操作。

实时工作流的最近消息默认最新在前，完整回复及工具日志仍按现有规则分流。
每轮摘要显示用户、时间、队列状态和最近已发生的阶段；异常直接显示原因。
点选消息查看正文、回复全文、各阶段状态和耗时，没有证据的阶段不推断成功。
消息搜索筛选当前已加载的记录，可按用户、UID、群成员及 ID 搜索。

收发队列分为：

| 分区 | 展示顺序 |
|---|---|
| 待处理 | 实际队列序号升序 |
| 异常待核对 | 首次失败时间升序，同时间按队列序号 |
| 历史记录 | 队列序号降序，最新在前 |

三个列表（待合并、模型批次、发件）各自分页，每页50条。
状态筛选只在当前分区内生效；搜索筛选本页。
顶部数量是全队列统计，列表和会话摘要按筛选展示。
异常任务保留“重试／确认已发／立即丢弃”及确认弹窗、审计、恢复命令。
队列调度和失败超时规则没有因页面排序改变。

### 模型失败自动恢复（2026-10-21）

- Butler 明确确认未提交模型输入时，沿用原请求 ID 自动重试，最多尝试3次，等待5／15秒。
- 已提交输入后的超时、断流、进程中断等结果未知任务不自动重放，避免重复执行工具。
- 没有发件结果的失败批次从首次失败起最多阻塞 `queue.failure_discard_seconds`（默认180秒）；
  到期保留消息、错误和审计，将批次结束，允许该会话后续消息继续处理。
- 历史异常没有结构化失败事件时，使用原 `finished_at` 计算期限；重启不重置期限。
- 安全重试耗尽时提前结束失败批次；正在运行的模型请求及已生成发件的批次不被该巡检打断。
- 看板显示下次重试、期限、自动恢复审计；“模型失败已结束”与成功回复分开显示。
- Codex 旧线程恢复被 RPC 拒绝时尝试新建同身份、角色、权限的会话，用户记忆与提醒保留；
  该新会话不携带旧对话上下文。失败详情经脱敏写入 Butler 控制台、运行记录和队列错误。
- 本次需手动重启 Butler、wxbot 和 log，由 wxbot 在运行时处理旧异常；本次没有修改真实队列。

## 配置

六个分类：基础连接、微信收发、模型后端、联系人与策略、日志、高级配置。
默认进入基础连接；搜索覆盖所有分类，搜索结果不受当前分类限制。
未启用模型后端、旧兼容配置、运行事实及固定规则放在高级配置中。
统一来源启用后，角色、工具权限、心跳、订阅及监听在“联系人”维护；配置管理显示唯一数据库来源，退役名单字段只读。未迁移安装保留旧配置兼容入口。

常见参数使用开关、枚举、数字、字符串列表和联系人表单；复杂结构支持高级JSON。
列表与联系人表单保留未编辑字段；JSON草稿无效时改用JSON编辑器修正。
参数来源、原键名在详情中，生效方式直接显示在参数说明下。

有改动时底部出现保存栏，显示修改数量和涉及文件；每次保存一个来源文件。
切换分类或业务页面不丢草稿，保存其他文件也不覆盖本文件的草稿和原版本。
仍使用原来的类型与权限校验、注释保留、备份、原子替换和409版本冲突保护。
密钥原值不回传；替换值只在密码控件及页面内存中保留，不写入HTML或浏览器存储。

角色／白名单／分组在后续读取时生效；wxbot、Butler、log启动参数仍需手动重启对应服务。
页面不会自动重启服务，不把文件值当作运行进程已经加载的值。

## 查询接口兼容

- `GET /api/flow` 增加可选 `order=asc|desc`，排序在分页之前。
- `GET /api/wxbot` 增加 `flow_order`，配合原来的 `flow_contact`、`flow_offset`。
- `GET /api/queue` 增加可选 `scope=active|issues|history`、`order=asc|desc`，及
  `inbox_offset`、`batches_offset`、`outbox_offset`；省略仍沿用原查询行为。
- 配置行增加展示元数据 `choices`、`widget`，写接口及规范路径不变。
- 前端静态资源仅由 `/app/assets/` 提供构建产物，路径必须落在该目录内，不能用于读取任意文件。

记忆／模型事件显示接口当前读取范围（最多100条记忆、100条事件），支持会话和内容筛选。
提醒统一在定时任务查看，服务端在截取前优先读取待执行提醒并按到期时间排序。
