# 自己发送的消息误入收件队列

## 排查依据

- sender 依赖截图像素；旧算法把条目顶部中央单点当背景，宽气泡覆盖此点时可能反转左右像素分数。发送缓存只处理 unknown，不能纠正 other。
- UI 主循环在发送确认之前轮询收件；成功确认自己的气泡后也未同步收件快照，存在两次截图得出不同方向的窗口。
- 本机持久记录最新到 2026-10-21 20:13；对两个已知队列库只读检查，未找到一小时内发件与后续收件正文完全一致的记录。因此这些是源码确认的缺陷，尚不能断言覆盖用户本次现场的所有触发条件。

## 修改

- 背景取样改为左右外侧边缘的中位色，并要求两侧背景一致；只统计头像高度范围，截掉头像的行不猜方向。
- 回车后由发送确认流程读取该会话，避免普通轮询先把气泡入库；确认成功时用同一份快照采集并发到达的用户消息，再推进收件锚点。
- 同步成功记录“收件防回流”日志，不包含聊天正文。
- 未增加按文本全局屏蔽，用户发送相同文字仍按消息方向判断。

## 检查与生效

- 修改文件通过 AST 静态语法检查；本次未新增或运行自动测试，未进行真实微信收发验证。
- 未启动、停止或重启服务，未改配置或清理现有业务队列。
- 由用户在 IDE 手动重启 wxbot 加载；Butler 和 log 无需重启。
