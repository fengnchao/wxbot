# Telegram 窗口转发新闻接入设计（待确认）

## 目标与路径

使用已登录的 Telegram Desktop，监听配置的新闻频道，模拟将新消息转发给安装者的机器人。机器人通过 Bot API 收件，Butler 按现有新闻分组投递到微信。无需个人账号 api_id/api_hash。

链路：频道窗口 → 模拟转发 → Telegram 机器人 → Butler 持久收件队列 → wxbot 发件队列 → 微信。

## 首版范围

- 正文、图片、图片说明、多图消息以及链接。链接在微信按文字 URL 发送，不承诺复刻 Telegram 预览卡片；隐藏在文字中的 URL 由 Bot API 消息实体提取。
- 视频、音频和文件暂不自动发送；记录不支持类型，避免静默遗漏。
- 转发仍受来源频道的内容保护限制；禁止转发的消息记录原因并跳过，不绕过限制。
- 机器人仅接受配置的转发账号和接收会话，新闻作为内容处理，不把它当作工具指令。

## 需要补充的能力

当前 butler/telegram 是个人账号文字转发服务；butler/push.py 到 wxbot 的接口只有 contact/text。新增 Bot API 接收器及媒体下载，并扩展 Butler/wxbot 的附件与图文队列；仅实现模拟转发不足以完成图片到微信的投递。

Telegram 窗口自动化单独封装。开发前检查实际客户端控件、消息边界和转发操作能否稳定识别。Telegram 与微信的鼠标、键盘、剪贴板操作通过跨进程互斥协调；网络等待不持有桌面操作锁。

## 队列与恢复

- 首次启动建立消息基线，不自动转发已有历史。
- 新消息先持久化候选任务，再进行模拟转发。可取得来源消息链接/ID 时优先作为去重依据；无法可靠定位消息时暂停并记录，不声称能够完整补收离线消息。
- Bot API 收件持久化后才推进更新游标，按更新/消息标识去重；保留来源标识用于跨阶段关联。
- 多图及说明组合成一个业务任务，微信侧逐项保存发送回执，避免图片与文字错配。
- 模拟转发结果不确定或微信发送结果不确定时不自动重复；已确认失败与未确认结果分别展示。
- log 展示发现、转发、机器人接收、附件下载、微信投递各阶段与失败原因。

## 配置与操作边界

独立机器人配置：启用开关、Token、允许的账号/会话、来源频道、缓存路径及轮询参数。Token 仅本机填写、不回显、不提交 Git；现有个人账号接收配置保持独立。

不启动或重启现有服务。实机转发及微信发送需用户明确授权；本设计确认后再实现，验证范围另按用户授权执行。
