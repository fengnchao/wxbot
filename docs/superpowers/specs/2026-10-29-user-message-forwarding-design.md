# 指定联系人消息转发

用户指定接口：`POST http://127.0.0.1:8790/v1/message`，JSON 请求体为
`{"code":"101","text":"你好"}`，`Content-Type: application/json`。

在 Butler 调用模型、读取记忆、认领补发或处理自身命令前，匹配私聊的微信联系人名称。
命中启用的 `[[message_routes]]` 后仅转发 `code` 和原消息正文；任何 2xx 视为接收成功，
响应正文不解析、不投递到微信。其他联系人及群聊沿用原流程。

每项包含 `contact`（精确匹配窗口名称）、`url`、`code`、`enabled`（默认 true）、
`timeout`（默认 10 秒）。一个联系人最多一项，非法配置拒绝加载与保存。
配置管理提供 JSON 数组编辑入口。禁用或删除规则即可恢复默认模型处理。

HTTP 失败、超时或重定向均记录失败，不回退到 Codex、不发送错误文案、不自动重放。
接口未定义幂等键，因此请求体不增加字段；超时不能证明对端未收到。
转发不附带身份凭证、角色、记忆或其他用户上下文。

## Approaches

- Butler 前置转发（采用）：保留现有鉴权、身份观测与收件队列，分流职责留在业务服务。
- 切换全局模型后端：现有全局开关会影响其他联系人，也不符合该接口的单向投递格式。
- wxbot 自行分流：会把业务配置复制到 UI 收发模块，没有必要。

不修改真实运行配置、不重启服务、不向实际接口或微信发送测试消息。
转发对象是 wxbot 已交给 Butler 的私聊文本批次；wxbot 本地斜杠命令仍由 wxbot 处理。
