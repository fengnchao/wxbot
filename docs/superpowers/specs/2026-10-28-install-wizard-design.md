# 安装引导与配置文件整理

## 用户要求与已确认选择

删除根目录的示例配置和配置编辑锁文件，增加安装引导，填写本地智能体、消息接口等连接信息。用户已选择：安装时可选本机 Codex、已有 Butler HTTP 接口、OpenAI 兼容 HTTP 接口。

用户进一步要求：有效的 `bound_users / bound_groups` 和人工群成员昵称映射移入数据库，其他配置优先使用默认值；安装引导说明更换电脑时哪些微信窗口设置需要检测。本文已纳入这些调整；用户已确认开始实施，并明确不接入 Grok Bot。

用户最新要求：`config.butler.toml` 中的 `[[contacts]]` 绑定也迁入数据库，与 wxbot 共用用户/会话目录；`config.log.toml` 中的 `sources` 改成相对路径。

智能体选择：Codex、Hermes、OpenClaw、Cursor、DeepSeek、已有 Butler 和自定义接口。用户明确取消 Grok Bot 接入；不显示 Grok Bot 选项。兼容的模型 API 可使用自定义协议连接。

## 方案选择

- 直接删除模板会破坏现有 `butler init`、Telegram Bot 初始化和部分发布检查，因此不采用。
- 把模板换一个目录仍保留了模板文件，不能满足删除要求，因此不采用。
- 采用程序内默认配置加命令行向导：初始化不依赖模板文件，安装脚本进入向导，运行配置按需生成。

命令行沿用现有 `scripts/setup.ps1`，避免额外网页服务、端口和依赖。新增 `python -m butler setup`，直接运行该命令也能进入同一个向导；保留非交互 `python -m butler init`。

## 安装步骤

1. 选择智能体/模型服务及实际接入方式，详见下节；保留已有 Butler 和自定义 API 入口。
2. 填写相应连接信息。
   - 本机 Codex：模型名可留空，使用专属本机登录目录；不要求填写不存在的 Codex HTTP 地址。
   - 已有 Butler：填写基础地址或完整 `/v1/handle` 地址，以及 Bearer Token。
   - Hermes、OpenClaw、DeepSeek、Grok 模型 API 及自定义兼容服务：按下文供应方/协议显示地址、模型或 Agent、API Key/Token 字段。
   - Cursor：按下文无界面 CLI 接入显示程序位置、专属目录和登录/Key 选项。
   - 其他 OpenAI 兼容服务：填写完整聊天接口地址，例如 `http://127.0.0.1:8000/v1/chat/completions`、模型名和可选 API Key。
3. 设置本机 wxbot 消息服务监听地址和端口，默认 `http://127.0.0.1:8765`；输入基础地址或 `/send` 地址均可，生成对应外发配置。Token 默认安全随机生成，也可输入已有 Token。
4. 本机 Codex 模式设置 Butler 接收服务地址，默认 `http://127.0.0.1:8770`，自动关联 wxbot 与 Butler 的地址和 Token。
5. 设置管理台本机监听地址，默认 `http://127.0.0.1:8788`，以及机器人在微信中的昵称。监听名单、监听范围和昵称属于通道设置，由数据库与管理台维护，不再要求用户手写进 TOML。
6. 显示隐藏密钥的配置摘要，用户确认后创建运行配置；取消不写配置。
7. 输出本次选择对应的启动命令、接收和发送接口地址、后续登录/诊断步骤。安装过程不自动启动、重启服务，不调用模型，不发送测试消息。

地址只接受有效 HTTP/HTTPS URL，校验端口、路径、查询参数及片段；拒绝 URL 内嵌账号密码。已有 Butler 输入末尾 `/v1/handle` 时规范化为基础地址；OpenAI 兼容接口保留完整请求路径。对于本项目自己启动的本机 HTTP 服务，只接受 HTTP 回环监听地址，禁止把任意远端地址当作本机监听地址。

消息服务为当前 wxbot HTTP 服务，不泛化为任意第三方消息协议。已有外部 Butler 的主动推送目标仍需由其拥有者配置，向导只展示本机 wxbot 发送地址和 Token 对齐要求，不修改外部服务。

## 配置与运行模式

默认值移到代码模块，通过新对象生成 TOML，确保每次初始化的配置互不共享可变状态。删除全部七份 `config.*.example.toml`。保留精简的实际 `config.*.toml`，主要保存接口连接、鉴权和显式高级覆盖项；默认值不逐项展开。业务和通道名单保存在数据库，不合并服务运行配置，不复制其他安装的凭据或数据。

向导默认仅用于首次安装：检测到已有实际配置时显示保留结果，避免覆盖或悄悄切换现有后端；可通过 `--directory` 在新目录安装。已有接口配置调整继续使用现有管理台。非交互 `init` 保持幂等。本机旧通道数据迁移是单独、幂等的升级步骤，不借此重写模型、地址、Token、其他高级覆盖或无关注释。

接入形态沿用现有处理器与 Butler 的后端接口，并扩展有依据的供应方适配器，不添加假 HTTP Codex 后端：

| 选择 | wxbot 处理器 | 本机 Butler | Codex 登录 |
|---|---|---|---|
| 本机 Codex | ButlerProcessor | 启动 | 需要 |
| 已有 Butler | ButlerProcessor，使用用户地址 | 不启动本机副本 | 不要求 |
| OpenAI 兼容 | OpenAICompatProcessor | 不启动 | 不要求 |

接入方式写入现有运行配置中的明确字段，不新增第四份安装状态配置。`start` 和 `doctor` 根据该模式选择本机服务和检查项，避免外部模式启动错误的本机 Butler 或要求无关的 Codex 登录。缺少新模式字段的旧安装维持原行为。

管理台在外部 Butler 和直接 API 模式只提供本机通道、配置、队列信息；用户、记忆、心跳等由对端自己的管理台维护。外部聊天连接使用配置的远端地址和凭据，管理操作不得误用本机默认 Butler。实施中自动审批拒绝向远端发送管理数据，因此采用此更窄的权限范围。

可选 Telegram 功能保持关闭并按需初始化：Bot 初始化改用程序内默认值；个人账号接入提供初始化命令；桌面转发继续由管理台保存配置。不因删除模板而失去任何现有可选功能。

## 智能体和模型服务的选择

安装体验统一为“选择服务 → 显示必要连接字段 → 本地校验 → 显示能力与配置摘要 → 确认保存”。底层按真实协议选择适配器，不单靠品牌名称判断请求/回包格式。

| 选项 | 接入方式与字段 | 范围 |
|---|---|---|
| Codex | 现有 SDK/本机运行时；专属本机登录或受支持的 API Key 模式；HTTP 地址不是必填项 | 保留现有完整回复、会话、权限边界，不导入其他安装的登录 |
| Hermes | API Server 地址、API Key、模型/路由选项 | 复用现有 Hermes 适配器和会话隔离，不退化为丢失身份元数据的普通请求 |
| OpenClaw | 已启用 HTTP 对话端点的 Gateway 地址、Token、目标 Agent | 适配兼容 Chat Completions 的真实端点，按用户/会话稳定隔离；提示对端端点需要先启用 |
| Cursor | 官方无界面 CLI；程序位置、专属运行目录、登录或 Cursor API Key | 独立 CLI 适配器，不能假设 Cursor 应用提供通用 `/v1/chat/completions` 服务 |
| DeepSeek | API 地址、Key、模型名 | 兼容 Chat Completions 的模型服务预设，不冒充一个已配置好工具的完整智能体 |
| 已有 Butler | 基础地址或完整 `/v1/handle` 地址、Bearer Token | 复用已有 Butler 接口，避免启动第二份本机 Butler |
| 自定义 API | 协议类型、Base URL/完整端点、鉴权方式、模型名或 Agent 标识、超时 | 先覆盖明确支持的协议；未知 JSON 格式需要显式适配，不宣称任意 API 都能只填地址和 Key 接通 |

模型名和端点可以修改，不把当前品牌默认模型硬编码成不可变值。供应方预设和能力声明保存在程序代码中，避免再次产生一堆示例配置。品牌预设与传输协议分离；标准兼容服务复用驱动，特有会话、流式事件或鉴权采用独立适配。

Cursor/Codex CLI/SDK 使用专属隔离工作目录和明确的工具权限；微信输入不成为本机命令执行授权。不使用 `--force / --yolo` 等跳过审批选项。CLI 用固定程序与参数数组调用，Key 通过受控环境或专属凭据存储传入，不拼 shell 命令、不进入进程参数或日志。检测到交互审批、超时、进程中断或不完整结果时不得把部分输出当成已完成回复发送。

向导按适配器能力显示所需字段，API Key/Token 隐藏输入并在摘要脱敏；不要求本机登录模式填写虚构服务地址。默认只做格式、本机依赖和可用的只读连接检查，不自动发起收费模型调用或真实消息发送。

简单模型 API 的对话能力与完整智能体的工具/记忆能力不能混淆；管理台只显示当前后端确实支持、且已授权的功能。无论使用哪种适配器，wxbot 仍负责微信 UI 和投递队列；本地身份、权限和业务由 Butler 服务层执行验证，不能由外部回包中的自称身份授予权限。

## Butler 与 wxbot 共用数据库用户目录

当前绑定列表并非完全无用：主窗口且 `listen_all=true` 时不作为收件白名单；`listen_all=false` 或独立窗口模式仍需要它们，群名单还用于会话类型提示。迁移必须保存现有监听范围，不能擅自把“全部监听”改成“只监听绑定”，也不能反过来扩大范围。

沿用现有 `data/business.sqlite3`，为用户/会话目录、监听设置和昵称映射增加关联表，替代上一版另建通道设置数据库的方案。Butler、wxbot 和 log 使用同一目录及稳定标识，不分别维护一份联系人副本。数据库位置由统一路径解析入口确定，不能各自猜测并创建不同的库。它独立于收发队列，清理队列不会清除用户目录或人工昵称。

用户目录、已确认身份与权限的业务写入由 Butler 用户服务层统一管理；wxbot 读取所需的监听/显示视图并提交观测，不直接写确认身份、权限或个人记忆。相关本地目录初始化与管理能力不依赖 Codex 登录或本机模型进程；已有外部 Butler/OpenAI 接入仍可使用本机通道目录。外部 Butler 自己管理其身份权限，不复制其数据库，不把本机标识冒充成远端授权凭据。

存储内容包括：

- 共用的会话名称、私聊/群聊类型、显示昵称及关联的稳定用户/会话 ID。
- Butler 原 `[[contacts]]` 中的 `uid / profile / label / session_key` 路由信息；兼容现有后端隔离逻辑，不把旧 `uid` 强行替换为现有 `user_id`。
- wxbot 的监听范围、私聊和群聊名单、监听启用状态、机器人提及昵称。
- 按 `群会话 + 成员观测标识` 区分的昵称映射，记录人工维护/自动学习来源及是否待核对。
- 同一安装的旧配置迁移状态，避免再次启动时用旧 TOML 覆盖管理台的新修改。

管理台从该存储展示和修改通道设置。人工别名与自动学习记录分别保存，明确优先级；自动采集不得覆盖人工确认内容。现有队列库中的 `group_member_names` 自动学习记录也需转入统一读取路径，避免两份互相冲突的昵称来源。

“是否监听”与“Butler 身份/权限是否启用”是不同状态；共用用户信息不等于把这两个开关合并。只存在于 Butler 配置中的联系人不能因此自动加入受限监听白名单；只存在于 wxbot 名单中的会话也不能因此自动获得个人记忆或工具权限。已有同一人跨群关联、记忆归属和已确认绑定保持原样。群会话和群成员是父子关系，不把整个群当成一个个人用户。

迁移以现有稳定标识和可靠会话匹配为依据，合并重复的会话元数据；名称、类型或旧路由冲突时保留冲突供管理台核对，不靠同名强行合并不同的人。

旧全局 `member_names` 没有群范围且可能来自未核对的头像网格，不能盲目复制到所有群。能够可靠归属的记录按群迁移，无法归属的保留为待核对旧别名，在管理台选择对应群；这类显示名称不能被标成已确认用户身份，也不能自动授予长期记忆、工具权限或真正 @ 的授权。

迁移先在临时库测试，并以事务完成写入和核对；成功后才原子移除本机 TOML 中已迁移的字段，保留地址、密钥及其他配置。失败时旧配置仍可用，记录迁移状态以便安全重试。运行时不因迁移重放历史消息或发出微信消息。

## log.sources 相对路径

本机当前四个数据源都在项目目录内，保存为：

```toml
[sources]
home = "data"
wxbot_config = "config.wxbot.toml"
butler_config = "config.butler.toml"
groups_file = "data/cache/butler_groups.json"
```

所有文件内 `sources` 路径以实际加载的 `config.log.toml` 所在目录为基准，在读取时解析成内部绝对路径，不依赖启动时的工作目录或源码安装位置；由 `LOG_CONFIG` 指定另一份配置时也遵循这一规则。空路径继续表示原有的自动选择语义，绝对路径保持兼容，命令行/环境变量覆盖优先级不变。

安装引导及 `init` 生成相对路径；本机现有 log 配置只替换等价路径写法，解析后仍指向原来的同一文件，不修改其他设置。自定义同盘路径可以包含 `..`；跨 Windows 盘符无法表示成相对路径时保留绝对路径并说明。管理台保存和显示要区分文件内相对值与实际解析结果，不在一次保存后又写回机器专属绝对地址。

同一安装的数据库、队列、配置等相对运行路径也应以对应配置文件目录为基准，避免新目录安装时误用源码目录中的数据。

## 微信默认配置与换电脑

默认使用 `wechat.mode="main"`。`mmui::ChatSingleWindow` 为当前实现中的独立聊天窗口类名，不是机器编号；主窗口使用 `wechat.main_window.window_class`，当前默认 `mmui::MainWindow`。主窗口模式中兼容读取独立聊天窗口的路径仍可能使用前者，不能把它误认为在所有主窗口场景都无效。

普通安装不要求用户填写窗口类名或模式，程序使用默认值。更换电脑且微信界面版本相同时通常沿用默认；微信版本、控件结构、显示缩放等变化可能需要检测或校准，不保证所有电脑通用。安装/诊断提供只读窗口和必要控件检测，失败后再提示高级覆盖或探针步骤；不盲目改类名、不激活聊天、不发送测试消息。头像匹配异常保持未知/待核对，不根据旧哈希自动确认身份。

## 编辑锁处理

删除现有根目录 `*.edit.lock`，但不取消进程间并发保护。新编辑锁放在运行数据/缓存的专用锁目录，使用规范化配置绝对路径的哈希区分目标，统一由现有 `config_lock` 入口管理；不得在解锁时直接 unlink 仍可能被其他进程使用的共享锁文件。

清理旧锁前尝试取得独占锁；正在使用的锁暂缓删除并明确报告。现有服务由用户自行重启加载新代码，旧进程在重启前可能继续使用旧锁位置；不得伪称文件迁移自动更新了运行进程。队列运行锁、Telegram 会话锁不属于配置编辑锁，不删除。`uv.lock` 是依赖版本文件，保留。

## 验收

- 源码与安装/发布流程不依赖任何示例 TOML 文件。
- 所有已实现的接入形态生成正确处理器、地址、鉴权和启动步骤；本机地址和 Token 自动保持一致。
- 智能体/模型预设显示实际所需的地址、Key、登录或 CLI 字段，按协议选择驱动；未提供或未验证的 Grok Bot 消息接口不会被显示为已支持。API/CLI 不完整结果不得投递。
- 无效地址、非法端口、取消和中断不会生成不完整的运行配置；密钥输入和摘要均不泄漏。
- 已有接口、Token 和无关配置/注释保持原样；仅在数据库迁移确认成功后移除已迁移的通道字段，初始化及迁移多次不覆盖新数据。
- 监听名单、人工昵称和既有自动学习昵称可以在数据库中统一维护，按群隔离；清理收发队列不删除这些数据。
- Butler 联系人绑定和 wxbot 监听信息从同一个数据库目录读取，旧 uid/Profile、已确认身份、记忆归属和权限不被重建或扩大。
- 保持原监听范围；历史未核对别名不自动升级为身份、权限或提及授权。
- log.sources 保存相对路径后，从不同工作目录启动或整体搬移安装目录，仍解析到对应配置目录下的数据；环境覆盖和历史绝对路径继续可用。
- 缺省主窗口/窗口类名配置可正常加载，旧显式覆盖继续生效；只读检测失败时提供校准提示。
- 配置编辑仍有跨进程互斥和版本冲突保护，根目录不再生成新编辑锁。
- 仅使用临时目录、假接口及假投递验证，不访问真实剪贴板，不执行真实微信发送，不自动重启任何服务。
- 执行安装、CLI、配置编辑、Telegram 初始化、发布检查及受影响管理台测试；独立审查后交付。
